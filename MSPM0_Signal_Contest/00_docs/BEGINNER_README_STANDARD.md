# Beginner Documentation Layer 标准

本标准用于正式模块的 README、公开头文件注释和教学示例。目标读者会 C 语言与 CCS 建工程，但不假设其已理解 DriverLib、Timer、ADC、DMA 或 Event。文档的目的不是让用户盲贴代码，而是让其可以独立写自己的 `main.c`。

## 1. README 固定结构

每个正式模块按实际需要采用以下顺序。无硬件依赖的纯算法模块可以省略 SysConfig，但必须明确写“本模块不需要 SysConfig”。

1. 一句话说明：先用日常语言说明模块做什么。
2. 什么时候用 / 不要用：给电赛题目场景和反例。
3. 先看懂原理：优先用 ASCII 数据流图说明输入、处理和输出。
4. 输入、输出与前后模块：写明数据类型、单位、所有权和典型模块链。
5. 30 秒接入与复制文件：列出真实需要复制的源、头和共同依赖；不把旧兼容层混入正式入口。
6. SysConfig / Pin：硬件模块给 CCS GUI 步骤、每个字段的含义、原因和何时改；不要求用户编辑生成文件。
7. 参数教程：按“必须理解 / 出问题再理解 / 高级”分级。每个可调参数必须说明含义、单位、影响、推荐或计算方法、何时改、错误后果及是否常改。
8. 调用顺序：给 Init、Set、Start、等待/回调、读取、处理、下一帧的流程图，并标注执行频率。
9. API 教程：公开头文件中的每个 API 都要有用途、调用时机、逐参数、真实返回值、最小片段和注意事项。禁止仅列函数名。
10. 首次建议、最常改参数、不要这样做、常见错误 FAQ、完整使用案例与模块链。

## 2. 参数与数字规则

- 用户能调整、会影响题目结果或资源的项属于【比赛必须会】；DMA 通道、Event 编号等属于【出问题再理解】；多缓冲等属于【以后进阶】。
- 不能出现无来源的数字。`65536U`、`1024U`、阈值、时间常数、分频和缓存长度都要解释单位、硬件或算法来源、是否可改。
- 有相互关系时写公式和算例，例如 `Tframe = N / Fs`、`points_per_cycle = Fs / f_signal`、`delta_f = Fs / N`。
- 文档中的实例名、返回值和默认值必须来自当前 `.h`、`.c`、示例、SysConfig profile 或测试，不可按名称猜测。

## 3. 示例规则

每个正式模块提供同目录的 `README_MINIMAL_EXAMPLE.c` 和 `README_FULL_EXAMPLE.c`。

- MINIMAL：可作为独立 `main.c` 编译的最短正常流程；顶部集中列出“用户通常只需要修改这里”，使用指定成员初始化，关键教学注释使用中文。
- FULL：在正确的调用顺序中演示全部公开 API；特殊 API（例如取消、停止）用 `#if 0` 隔离并说明适用条件，不为覆盖率制造危险顺序。
- 两类示例都要展示结果如何读取以及下一步可接什么模块。示例中的 Buffer 在 DMA/异步操作完成前不得读取或改写。
- README 代码块若标记为可编译验证，必须与对应源文件逐字一致；示例文件不是同一工程的第二个 main，用户只能选择其中一个加入 Build。

## 4. 公开头文件规则

每个面向用户的 struct 成员、enum、宏和函数使用中文 Doxygen 内容。保留 `@brief`、`@param`、`@return` 标签；实现内部的稳定英文注释不强制机械翻译。函数的返回说明只能列该实现实际可能返回的值。

## 5. 验收清单

- README 提到的 API、类型、成员、实例名均与当前源码一致。
- MINIMAL 与 FULL 均存在，中文注释完整，初始化不用位置初始化造成魔法数字。
- 有硬件依赖的模块明确 SysConfig 配置、Pin 可替换原则和生成宏要求。
- 文档不把 ADC 时钟误称为采样率，不要求手改 `ti_msp_dl_config.c/.h`，也不在 ISR 中建议执行大计算。
- 修改后运行仓库已有文档一致性检查及与该模块相关的复制构建检查；若没有实际板测，明确写构建验证，不虚称板级验证。
