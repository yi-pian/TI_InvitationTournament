# 模块设计准入清单

每写一个模块前做设计审查，完成后再做一次验收。任一关键项为“否”，模块不得接入综合应用。

## 十项硬门槛

- [ ] 能否由一个只做一件事的 Demo 独立测试？
- [ ] 输入、输出、单位、范围和所有权是否明确？
- [ ] 比赛常改参数是否集中在 config struct、配置头或 `.syscfg`？
- [ ] 是否只使用模块私有 `static` 状态，避免散落的全局 flag？
- [ ] 输出数据类型能否直接交给至少一个下游模块？
- [ ] 换 ADC 通道是否只改 `.syscfg`，并保持生成实例名稳定？
- [ ] 换采样率是否只改一个应用配置，并能取得实际值？
- [ ] 换 1024/4096 点是否只改一个配置，且有 RAM 占用说明？
- [ ] 不使用时能否移除源码和对应 SysConfig 实例，不牵连无关模块？
- [ ] 新同学只看 README，10 分钟内能否接线、编译、运行、判断对错？

## 接口审查

- [ ] `Init/Start/Stop/Process/GetResult` 的职责没有混在一起。
- [ ] API 不暴露寄存器操作，不要求应用层知道 DMA channel 编号。
- [ ] 缓冲区由谁分配、容量多大、何时可读写已经说明。
- [ ] 状态采用 `MODULE_IDLE/RUNNING/DONE/ERROR`。
- [ ] 参数错误、忙、越界、未初始化有明确返回码。
- [ ] ISR 短小，没有阻塞 UART、浮点重计算或长循环。

## 配置与资源审查

- [ ] `.syscfg` 中实例使用语义名称，例如 `SIGNAL_ADC`，不是把 `ADC0` 写死到应用 API。
- [ ] Timer 时钟源、分频、预分频、LOAD 与实际频率关系已写清。
- [ ] ADC 引脚、通道、参考、采样时间、触发源、DMA 触发源已写清。
- [ ] 资源冲突和不可随意修改项已列出。
- [ ] 生成宏已经从实际 `ti_msp_dl_config.h` 核对。

## 验证与交付审查

- [ ] SysConfig 严格生成无 warning/error。
- [ ] 编译器开启 `-Wall`；关键模块建议额外用 `-Werror` 验证。
- [ ] 链接 map 给出 Flash、SRAM、主要缓冲区占用。
- [ ] README 包含接线、信号源设置、CCS 观察量和正确范围。
- [ ] 清楚区分“源码检查、生成、编译链接、烧录、实板波形”五级验证。
- [ ] `README.md`、`MODULE_CARD.md`、最小 Demo 与模块源码同步更新。
