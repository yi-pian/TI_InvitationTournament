# 从陌生模块资料整理出 MSPM0G3507 模块：小白教程

这份教程解决一个常见问题：手里只有 Arduino、STM32 或一堆截图/旧代码，怎样把它整理成知识库里“别人能看懂、以后能复用、不会误接线”的 MSPM0G3507 模块资料。

不要把目标理解成“把旧代码翻译成 C”。真正的目标是建立一条证据链：模块是什么、每根线做什么、通信怎么走、MSPM0 需要什么资源、怎样用最小实验证明它工作。

## 一、先分清三种东西

拿到资料后，先把内容分成三栏：

| 类别 | 你要记录什么 | 能不能直接当结论 |
|---|---|---|
| 资料事实 | 型号、控制器、分辨率、引脚名、命令值、时序图 | 只有能追溯到原文时才可以 |
| 迁移假设 | “可能是 SPI Mode 0”“这个脚可能是 DC” | 只能写成待验证起点 |
| 验证结果 | 编译通过、逻辑分析仪波形、实物显示结果 | 才能升级状态 |

旧代码中的 `PB5`、`GPIOB->BRR`、`digitalWrite()` 属于“原平台实现”，不是模块事实。换成 MSPM0 时必须重新做 SysConfig 和 DriverLib 适配。

## 二、六步整理法

### 第 1 步：给模块取一个不容易混淆的名字

优先使用“模块标注 + 控制器 + 接口”，例如：

```text
GMT024-01 / ST7789 / 2.4-inch / SPI TFT
```

如果只有“2.4 寸 TFT”，不要擅自写成 ST7789。把候选控制器写在“待确认”里，并保留原始文件名。

### 第 2 步：抄出引脚表，但不要猜电气属性

把资料中的每个脚写成一行：

```text
Pin name | direction | role | active level | voltage | evidence | confidence
```

例如 `SCK` 是时钟输出、`MOSI` 是主机到屏的数据线；`BL` 是背光控制，不能因为它也是 GPIO 就默认能直接由 MSPM0 供电。没有数据手册时，`voltage` 填 `UNKNOWN`，不要填“应该是 3.3 V”。

### 第 3 步：从代码抽取协议骨架

只抽取能迁移的内容：

1. 一次传输先发命令还是数据？
2. 命令和数据由哪根 DC/A0 线区分？
3. CS 在一个字节、一个命令还是整块像素期间保持有效？
4. SPI 是几位、哪个 mode、MSB 还是 LSB？
5. 像素是 RGB565、RGB666 还是别的格式？
6. 窗口命令怎样给出起止坐标？

把不确定项标为 `待逻辑分析仪确认`。对于 ST7789，`0x2A/0x2B/0x2C` 是窗口写入骨架，初始化寄存器表仍要以精确资料为准。

### 第 4 步：画 MSPM0 资源图

把模块角色映射成 MSPM0 资源，而不是直接照抄旧 GPIO：

```text
SPI controller -> SCK + MOSI
GPIO           -> CS + DC + RST + BL
电源/地        -> 外部接线和电气检查
```

在 SysConfig 中选择 SPI 实例、SCK/MOSI 引脚和 GPIO；保留项目已有资源，不要为了一个屏幕悄悄改掉 ADC、Timer 或 DMA 的占用。生成的 `ti_msp_dl_config.h` 是实际宏名的依据。

### 第 5 步：只做最小驱动

先写平台层，再写控制器层：

```text
平台层：spi_write、cs、dc、rst、bl、delay
控制器层：reset、init、set_window、write_pixels
图形层：fill、rectangle、text、bitmap
```

第一版只需要“复位 -> 初始化 -> 全屏纯色 -> 小矩形”。不要一开始搬运几千行字库和图片数组。这样白屏时能知道是电源/复位/协议问题，而不是图片数据问题。

### 第 6 步：按证据升级状态

| 状态 | 需要的证据 |
|---|---|
| `DOCUMENTATION_ONLY` | 已整理资料，但型号、电气或协议仍有缺口 |
| `DOC_VERIFIED` | 精确数据手册/原理图已逐项核对 |
| `COMPILE_VERIFIED` | MSPM0G3507 目标源码在当前 SDK/编译器下通过编译 |
| `BOARD_VERIFIED` | 实物显示正确，并有波形/测量记录 |

编译通过不等于接线正确；旧代码能在 STM32 上显示也不等于 MSPM0 迁移完成。

## 三、把结果写成知识库文件

每个具体模块目录至少放：

```text
display/<module>/
├─ README.md          # 人读：事实、接线、SysConfig、bring-up、排错
├─ MODULE_CARD.md     # 快速卡片：边界、接口、状态、限制
└─ DEVICE_CARD.yaml   # 机器读：状态、路径、依赖、验证证据
```

README 建议固定章节：

1. 模块身份和证据来源；
2. 接口/电源/逻辑电平；
3. MSPM0 角色接线和 SysConfig；
4. 协议与关键命令；
5. 最小 bring-up；
6. 常见故障；
7. 原始资料索引、未验证项和升级条件。

卡片里的状态必须和 README 一致。没有源码就不要填写 `driver_files`；没有实物就不要写 `BOARD_VERIFIED`。

## 四、ST7789 这次整理的示范

本库中的 [`display/st7789/README.md`](../display/st7789/README.md) 按上面流程记录了：

- `GMT024-01`、`ST7789V2`、240×320、RGB565；
- SCK、MOSI、RST、DC、CS、BL 的角色；
- Mode 0 只是待验证起点；
- `0x2A/0x2B/0x2C` 的窗口写入骨架；
- 旧 STM32 引脚不能直接复制；
- 当前没有 MSPM0 正式驱动，状态保持 `DOCUMENTATION_ONLY`。

这就是“整理完成但不夸大验证”的正确结果：本库已经提供 `signal_tft_st7789.c/.h` 和 `signal_tft_st7789_mspm0g3507.c/.h`，源码可编译；等你找到精确规格书并完成最小纯色测试，再把偏移、复位和初始化表改成该实物的最终值。

## 五、下次可直接复制的检查表

- [ ] 完整型号、控制器、尺寸和分辨率已记录
- [ ] 每个引脚有原文证据；未知项明确写 `UNKNOWN`
- [ ] VCC、IO 电平、背光电流已核对
- [ ] SPI/I2C/UART 模式、位序、速率有证据或标为待验证
- [ ] 旧平台 GPIO 已转换成 MSPM0 角色，而不是硬编码端口寄存器
- [ ] SysConfig 实例、PinMux 和生成宏已确认
- [ ] 最小测试只包含复位、初始化、一个固定输出
- [ ] 逻辑分析仪/示波器或万用表结果已记录
- [ ] `DEVICE_CARD.yaml` 状态与 README 一致
- [ ] 未把“能编译”写成“能上板”，未把“能显示”写成“比赛已验证”
