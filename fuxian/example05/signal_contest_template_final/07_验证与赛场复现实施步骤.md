# example05 步骤七：验证、记录与赛场复现

## 1. 每加一个模块就 Build

1. 只加双 ADC：接同一信号，确认两路 DMA 完成。
2. 加 ST7789：确认标题、黑屏和 8×16 字符。
3. 加 AD9833：示波器确认 PA12/PA9 输出控制下的 1 kHz、再确认 100 kHz 正弦；确认 TFT 的 PB9/PB8 刷屏不受影响。
4. 加一帧阻抗计算：确认 Vrms、Irms、|Z|、Phase 数值变化。
5. 加扫频：观察 32 个点的进度条从 1K 到 100K。
6. 最后加 RLC 拟合、带宽和 Q；用纯 R、纯 L、纯 C 和已知串联 RLC 逐个验证。

## 2. CCS/SysConfig 检查

- 保存 `.syscfg` 后点击 Generate；不手改 `Debug/ti_msp_dl_config.c/.h`。
- 核对 `SIGNAL_ADC_A/B`、`SIGNAL_DUAL_ADC_TIMER`、`SPI_TFT_INST`、`SPI_AD9833_INST`、`GPIO_AD9833_*` 和 AD9833 MCLK 宏。
- Refresh 工程；`.cproject` 已预置旧片内 DAC/DDS 源的 Debug 排除项，确认它们显示为 **Excluded from Build**，并确认所有 README 列出的 AD9833、双 ADC、扫频和 ST7789 `.c/.h/.inc` 在 Build 中。
- Clean/Build；若工具报告 warning，和 error 分开记录，不能把 warning 写成“无警告”。

本次整理时 `Debug/sources.mk` 和 `Debug/modules/subdir_vars.mk` 仍是复制模块前生成的旧列表，
`Debug` 下没有手工补写模块源文件；按赛场步骤在 CCS Project Explorer 执行 Refresh 后，再由
CCS 依据 `.cproject` 重新生成 source list，确认 AD9833 组合源纳入 Build。这样既不会手改生成
文件，也不会把“静态语法通过”误报成“完整 CCS 链接通过”。

## 3. 本次文件变更审计

允许修改的文件：

- `signal_config.h`：Fs/N/频率范围/AD9833 MCLK 和模拟前端换算宏。
- `signal_contest_template.syscfg`：双 ADC Timer 从 README 的 10 us 调为 2 us；新增独立 `SPI_AD9833`（SPI0：PA12/PA9、Mode 2）和 PA8 FSYNC，屏幕 SPI1 保持原配置。
- `main.c`：README 代码的组合、RMS/阻抗/RLC/Q 和显示状态机。
- `modules/README.md`：补充 example05 缺少的阻抗公式、调用顺序和 SysConfig 差异。
- 本组 `01_...md`～`07_...md`：比赛步骤和逐行说明。

禁止修改的文件：`modules/` 下所有模块 `.c/.h/.inc`、生成的 DriverLib 源文件和链接文件。

## 4. 自写代码的逐步复现顺序

1. 先只保留 `App_MeasureFrame()`，确认 DMA 完成后四个基础量变化；这一段对应 22_X 的“双路同步 ADC”小题。
2. 加入 `App_DrawStaticUi()`、`App_DrawLiveResult()`，确认 ST7789 的 8×16 字符和局部刷新；对应 22_X 的“TFT 显示”小题。本题不画李萨如图，因为题面要求的是数值测量页。
3. 加入 `App_RunSweepPoint()` 的 AD9833 设频调用，确认进度条从 1 kHz 到 100 kHz。
4. 最后加入 `App_FitSeriesModel()`、`App_DrawAnalysis()`，用纯 R/L/C 和串联 RLC 逐一验证类型、F0、BW、Q。

这里的每一步都可以在 CCS 中单独 Build；下一步只增加 main 的组合调用，不回头修改冻结模块。

## 5. 现场操作清单

1. 复制工程并打开 `01_模块选择与题目定义.md`。
2. 依次复制模块，Refresh，按每个 README 配 SysConfig。
3. 先跑双 ADC，再单独验证 AD9833，再接 ST7789，最后粘贴扫频和分析代码。
4. 输入纯 R：相位接近 0°，显示 R；输入纯 L：相位为正，显示 L；输入纯 C：相位为负，显示 C。
5. 输入串联 RLC：观察 `|Z|` 谷值、`F0`、`BW` 和 `Q`；与示波器/万用表参考值比较。
6. 调整 `SIGNAL_VOLTAGE_SCALE_V_PER_CODE` 和 `SIGNAL_CURRENT_SCALE_A_PER_CODE` 做前端校准。

## 6. 验证边界

源码和 SysConfig 可做静态/隔离编译验证；真实的 1 kHz～100 kHz AD9833 扫频精度、ST7789 偏移、
模拟前端增益和元件值仍需连接开发板实测。未连接实板时，结论只能写 `BOARD NOT_RUN`，
不能把仿真或编译结果写成比赛现场已验证。本次结果为：SysConfig CLI 通过、main 与模块
TI Arm Clang 语法检查通过；完整 CCS Clean/Build 链接和实板验证尚未执行。
