# example03 步骤 01：模块选择与题目定义

## 一、预测题目

**猝发/调制双路信号识别仪**：两路同步输入中，A 路是被测波形，B 路是同步参考或比较器标志。系统连续采集，识别每个数据块中的高电平猝发，统计猝发长度和高门限采样点数，并在 ST7789 上显示当前波形；4×4 键盘调整门限和切换 A/B 页面。

这是对往年信号题中“同步采样、波形显示、阈值测量、人机交互”的组合预测。它和 22_X 的静态一帧采集不同，重点覆盖连续采集、DMA 块轮转、事件缓存和状态显示。

## 二、比赛拆分顺序

1. 配置双路 ADC、Timer/Event 和 DMA，先确认一块同步数据能完成。
2. 启动连续采集，按完成块序号消费数据。
3. 在应用层加入 Ping-Pong 状态和 Ring Buffer，避免 DMA 写入正在处理的数组。
4. 对每块数据做门限检测，得到猝发首尾位置、长度和高门限点数。
5. 用 ST7789 局部刷新波形，用键盘调整门限和翻页。
6. 按源码、SysConfig、屏幕、键盘和实板顺序复现。

## 四、SysConfig 是否按 README

总体按 README 和 22_X 的已用资源配置：ADC0/PA25、ADC1/PA17、DMA_CH0/CH1、TIMG0、SPI1、ST7789 控制 GPIO 和固定矩阵键盘 GPIO。连续采集需要 README 中的 Timer 事件、DMA 完成中断和连续块模式；这些是硬件配置，不由 Ping-Pong/Ring Buffer 软件模块代替。

## 五、main 自写边界

`APP_BLOCK_*`、数组和页面状态是题目参数；`App_MapY`、字模显示、`App_ProcessBlock`、`App_HandleKey`、`App_ConsumeCompletedBlock` 是应用逻辑。模块只负责硬件采集、缓冲状态、FIFO、键盘字符和 ST7789 图形 API。
