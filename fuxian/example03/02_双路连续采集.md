# example03 步骤 02：双路连续 ADC 采集

## 一、SysConfig 配置

按 `02_acquisition/adc_dual_sync/README.md` 在 CCS 的 `Software -> Add` 中配置两个 ADC12、同一 Timer 触发事件和两路 DMA。沿用工程中的资源角色：

| 功能 | 本工程配置 |
|---|---|
| ADC A 输入 | ADC0 / PA25 |
| ADC B 输入 | ADC1 / PA17 |
| DMA | ADC A 使用 CH0，ADC B 使用 CH1 |
| 采样触发 | TIMG0 事件，10 us，即约 100 kSPS |
| 数据块 | 每块 256 个 `uint16_t`，连续轮转 2 块 |

保存后 Generate，只检查生成的实例宏、DMA 通道、Timer load 和 IRQ 名称；不手改 `ti_msp_dl_config.c/.h`。

## 二、从 README 复制到 main 的代码

初始化和连续启动调用保持模块 API 顺序：

```c
const signal_dual_adc_config_t adc_config = {
    SIGNAL_SAMPLE_RATE_HZ, CPUCLK_FREQ, 65536U
};
SYSCFG_DL_init();
SignalDualADC_Init(&adc_config);
SignalDualADC_StartContinuous(&g_adc_a[0][0], &g_adc_b[0][0],
    APP_BLOCK_SAMPLES, APP_BLOCK_COUNT);
```

- `adc_config` 的三个字段来自 README：目标采样率、Timer 时钟、Timer 最大计数。
- `SYSCFG_DL_init()` 由 SysConfig 生成，用于先打开 ADC、DMA、Timer 和 GPIO。
- `SignalDualADC_Init()` 只调用一次，保存时钟和采样率参数。
- `SignalDualADC_StartContinuous()` 把两路首块地址、每块点数和块数交给平台适配层。

## 三、自写变量逐行解释

```c
static uint16_t g_adc_a[APP_BLOCK_COUNT][APP_BLOCK_SAMPLES]; /* A 路的两块 DMA 存储。 */
static uint16_t g_adc_b[APP_BLOCK_COUNT][APP_BLOCK_SAMPLES]; /* B 路的两块 DMA 存储。 */
#define APP_BLOCK_COUNT (2U) /* 只保留两块，形成最小 Ping-Pong。 */
#define APP_BLOCK_SAMPLES (256U) /* 每块含 256 个 12 位 ADC 码。 */
```

二维数组在内存中连续排列，因此 `&g_adc_a[0][0]` 后面紧接着就是第二块。每一路占 `2 × 256 × 2 = 1024` 字节；两路共 2048 字节。采集硬件真正的块切换由 `signal_dual_adc_mspm0g3507.c` 完成，main 不直接写 DMA 寄存器。

## 四、和 README 的差异

README 的最小示例通常采一帧；本题调用模块扩展的 `StartContinuous`，让 Timer/ADC/DMA 在块边界持续工作。连续块接口已在工程复制的 ADC 模块中提供，main 只传数组和尺寸，没有改模块实现。
