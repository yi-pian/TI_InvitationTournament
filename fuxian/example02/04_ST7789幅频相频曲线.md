# example02 步骤 04：ST7789 幅频/相频曲线

本步骤在前面“DAC 输出扫频激励、双路同步 ADC 采集、键盘控制”的基础上，完成
ST7789 曲线显示和正式正弦激励。最终链路为：

`正弦波表 -> DDS -> DAC DMA -> 被测网络 -> 双路同步 ADC -> 幅值/相位计算 -> ST7789`。

为减小高频端的 DAC 阶梯，本工程把 DAC 更新率设置为 `1 MHz`。每个扫频点根据
`更新率/输出频率` 计算 DMA 缓冲长度，并限制在 2 到 2048 点之间；因此在 8 kHz
时约有 125 个 DAC 点/周期，不再是原来的约 12.5 个点/周期。

本步骤没有修改集成库中的任何 `.c/.h` 文件；所有模块文件均从
`MSPM0_Signal_Contest` 集成库复制到工程 `modules` 目录。

## 一、模块复制

本步骤新增或确认复制了以下文件：

- `signal_sine.c/.h`：按正弦函数生成 DAC 波表；
- `signal_dac_wave_table.c/.h`：检查波表参数并把归一化值转换为 DAC 原始码；
- `signal_math.h`：正弦模块使用的数学常量和辅助接口；
- `signal_dds.c/.h`：用相位累加器按目标频率从波表取样；
- `signal_dac_dma_mspm0g3507.c/.h`：用 DAC DMA 连续输出 DDS 结果；
- `signal_dual_adc_phase.c/.h`：计算两路同步采样信号的相位差；
- `signal_tft_st7789*.c/.h` 和 `signal_tft_st7789_font_data.inc`：ST7789 绘图和字库；
- 前面步骤已经使用的双路 ADC、扫频、矩阵键盘模块继续保留。

ST7789 部分从 README 复制 `SignalTFTST7789_MSPM0_Init()` 和图形 API。
正弦部分按照 `sine/README.md` 的最小调用形状，先准备
`signal_dac_wave_table_t`，再调用 `SignalSine_Generate()`；随后按照 DDS 和 DAC DMA
模块 README 的调用顺序初始化并输出。

### 一.一 SysConfig

本步骤没有新增或手改 `.syscfg`。继续使用工程中已经配置好的 SPI、TFT 控制 GPIO、
DAC、DMA、双 ADC、ADC DMA 和矩阵键盘资源。生成文件由 SysConfig 产生，未手改

不影响本次编译链接。

## 二、正式正弦激励

下面这段是从模块 README 的接口组合而来的应用代码，参数是本题的少量组合逻辑：

```c
#define DDS_TABLE_COUNT (256U)
static uint16_t g_dds_table[DDS_TABLE_COUNT];
static uint16_t g_dds_output[DDS_TABLE_COUNT];

signal_dac_wave_table_t sine_table = {
    g_dds_table, DDS_TABLE_COUNT, 12U
};
(void)SignalSine_Generate(&sine_table, 0.5f, 0.45f, 0.0f);
(void)SignalDDS_Init(&g_dds, g_dds_table, DDS_TABLE_COUNT,
    1000.0f, (float)SIGNAL_DAC_UPDATE_RATE_HZ, 0U);
```

逐行说明：

1. `DDS_TABLE_COUNT` 把波表长度固定为 256 点；这是 2 的幂，满足 DDS 模块的要求。
2. `g_dds_table` 保存一个周期的 12 位正弦 DAC 码；`g_dds_output` 保存 DDS 展开的 DMA
   输出数据。
3. `sine_table` 把数组地址、点数和 DAC 位数交给波表模块。
4. `SignalSine_Generate()` 使用 `0.5` 的直流偏置和 `0.45` 的归一化峰值，得到范围约
   为满量程 5% 到 95% 的正弦波，避免顶到 ADC/DAC 两端。
5. `SignalDDS_Init()` 设置初始输出频率和 DAC 更新率；扫频时由
   `SignalDDS_SetFrequency()` 修改频率，`SignalDDS_Fill()` 重新填充 DMA 缓冲区。

这里没有在 `main.c` 手写三角波或逐点计算正弦函数；波形生成由正式模块完成。

## 二、静态界面

`App_DrawStaticUi()` 只在上电、按 C 重扫或扫频点回到 0 时调用：清屏一次，画蓝色边框
和中线。它没有放入 ADC/DMA 中断，也没有每个点清屏，所以边框不会闪烁。

## 三、动态点绘制

`App_DrawPoint()` 是自写坐标映射：

- X 坐标用 `index/(SWEEP_POINTS-1)` 把扫频点均匀铺到 `PLOT_W`；
- Y 坐标把 0 到 1 的增益/相位归一值反向映射到屏幕高度；
- 两个边界判断把像素限制在绘图区；
- `FillRect(x-1,y-1,3,3,color)` 画一个小方点，避免 ST7789 没有 DrawCircle。

`g_curve==0` 显示增益，颜色为黄色；`g_curve==1` 显示相位，颜色为青色。
这是应用层逻辑，ST7789 模块只执行图形 API。

## 四、相位计算

相频计算复制集成库 `05_precision/dual_adc_phase_measurement` 的
`signal_dual_adc_phase.c/.h`，在每帧双路同步 DMA 完成后调用
`SignalDualADCPhase_Process()`。配置中的 `frequency_ratio` 为 `1`，因为被测网络
输入、输出频率相同。该模块内部完成动态中点、迟滞过零、插值和多周期平均；原先
`main.c` 中手写的 `App_FindCrossing()` 和 `SignalPhase_FromZeroCross()` 已删除，
不再参与计算。

## 五、自己编写的应用层代码

只保留以下少量组合逻辑，模块 `.c/.h` 没有改动：

- `App_PeakToPeak()`：遍历双路 ADC 缓冲区，找最大值和最小值，计算幅度差；
- `App_DrawPoint()`：把扫频序号和归一化增益/相位映射到绘图区像素坐标；
- `App_DrawStaticUi()`：上电时画标题、操作提示、蓝色边框和中线；
- `App_ClearCurve()`：扫频重新开始时只清除绘图区内部，再补画中线；
- `App_RunSweepPoint()`：串接停止旧 DMA、设置扫频频率、启动 DAC DMA、等待 ADC DMA、
  计算幅值/相位并画一个点；
- `App_DrawSampleRate()`：只清除并重画顶部的采样率数字区域；
- `SysTick_Handler()`：模仿 `22_X`，每 5 ms 调用一次键盘模块的
  `SignalMatrixKeypad4x4_ReadNewSymbol()`，只把稳定按键放入待处理变量；
- `App_ProcessKey()`：在主循环中处理待处理按键，A/B 选择曲线，C 重新扫频，D 切换采样率
  并刷新顶部数值。屏幕 API 不在中断中调用。

其中 ADC 等待使用有界计数，避免 DMA 中断异常时主循环永久卡死；这属于必要的少量
应用保护逻辑。
