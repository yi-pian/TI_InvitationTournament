# example04 审查与完善记录

本次按 22_X 的比赛现场检查方式，对 `main.c` 的屏幕、键盘和波形显示进行了预检查。

## 1. 发现并修正的问题

### 首帧采集停在等待状态

实物烧录后只显示蓝色边框和 `GEN`，说明 ST7789 初始化及静态页面正常，但 main 一直停在 `App_AcquireFrame()` 的 DMA 完成等待处。检查发现双 ADC 模块负责打开 DMA IRQ 的 NVIC，但当前工程还需要应用层打开 DMA 通道中断源；该步骤在 example03 中已有，example04 漏掉了。

之前曾在 main 的 `SignalDualADC_Init()` 后临时补上：

```c
DL_DMA_enableInterrupt(DMA,
    DL_DMA_INTERRUPT_CHANNEL0 | DL_DMA_INTERRUPT_CHANNEL2);
```

现在该调用已经正式封装进集成库的 `signal_dual_adc_mspm0g3507.c`，main 不再重复调用。模块根据 `SIGNAL_ADC_A_DMA_CHAN_ID` 和 `SIGNAL_ADC_B_DMA_CHAN_ID` 自动打开对应通道。本工程 SysConfig 中 CH1 使用 DMA 通道 0、CH2 使用 DMA 通道 2，因此 ADC DMA 可以进入模块的 `DMA_IRQHandler()`，`g_measurement_valid` 才能置位并绘制动态页面。

### 屏幕字体

原来动态页面的大部分字段使用 `TFT_ST7789_FONT_6X12`，与本题要求的统一大字体不一致，而且参数不易辨认。现已全部改为模块提供的 `TFT_ST7789_FONT_8X16`。标签、数值、波形页提示、捕获状态和校准提示均统一为 8×16。

### 屏幕局部刷新

数值字段先只清除右侧 104×16 像素，再绘制新数字；状态字段只清除自己的 240×16 区域。页面边框、标题和固定说明不在动态循环中重画。

当前页面底部还显示 `MODE:` 当前功能页、`IN:` 当前数字预输入内容，以及该页面常用按键提示。输入频率、幅度或偏置时，`IN:F=`、`IN:A=`、`IN:O=` 后会实时显示已经按下的数字；按 `#` 确认，按 `D` 取消。

### 频率/幅度确认后没有真正改变输出

检查发现旧版 `App_CommitInput()` 只修改了 `g_output_frequency_hz`、`g_amplitude_mv` 或 `g_offset_mv` 变量，没有重新调用 `App_ApplyWaveform()`。而 DAC DMA 正在循环播放已经生成的 `g_dac_output` 缓冲，因此屏幕参数会变、示波器输出不变。

现在确认输入后，如果参数确实发生变化，会执行：

```text
SignalDACDMA_MSPM0_Stop
→ Sine/Square/Triangle/Sawtooth_Generate
→ SignalDACWaveTable_Validate
→ SignalDDS_Init
→ SignalDDS_Fill
→ SignalDACDMA_MSPM0_Start
```

这样新的频率、幅度和偏置才会写入实际 DMA 播放数据。输入范围仍为频率 200～20000 Hz、幅度 10～1500 mV、偏置 0～3000 mV。

### DAC 输出残影检查

对比 `example02` 后发现，旧版 `example04` 固定用 256 点 DMA 缓冲。100 kHz 更新率、1 kHz 输出时，256 点包含 2.56 个周期，DMA 从末尾跳回开头时波形相位不连续，示波器会显示周期接缝残影。

现在参考 `example02`，按实际 DAC 更新率和输出频率计算 DMA 点数：

```text
output_count = 实际 DAC 更新率 / 输出频率
```

并限制在 `SIGNAL_DAC_OUTPUT_COUNT` 容量内，再用该长度调用 `SignalDDS_Fill()` 和 `SignalDACDMA_MSPM0_Start()`。这样每次循环播放整数周期，减少首尾跳变。仍建议 DAC 输出后增加重建低通滤波器，因为量化噪声和更新率镜像不能只靠软件消除。

### 矩阵键盘检测

原来 main 在主循环中直接调用 `SignalMatrixKeypad4x4_ReadNewSymbol()`。由于一次 ADC DMA 采集、FFT 和屏幕绘制会占用较长时间，主循环轮询并不能保证约 5 ms 的扫描周期，按键容易漏读。

现改为：

1. `SysTick_Handler()` 每 5 ms 调用一次 `SignalMatrixKeypad4x4_ReadNewSymbol()`；
2. 模块内部继续完成固定 GPIO 扫描、3 次消抖和鬼键过滤；
3. 中断只把稳定的新字符放入 8 字节环形队列；
4. main 用 `App_ProcessQueuedKeys()` 逐个取出并执行页面、参数和功能操作。

这与 22_X 的键盘扫描方式一致，避免在中断里执行 FFT、绘图或参数处理。

### 屏幕刷新与波形绘制

原来每次完成一帧测量后都调用 `App_DrawDynamicPage()`，会反复清空 4～316、28～233 的大区域，容易造成 ST7789 刷新闪烁和主循环阻塞。

现增加 250 ms 显示节拍：

- 测量和算法仍按采样帧运行；
- 屏幕动态内容最多每 250 ms 更新一次；
- 页面切换、参数确认、波形切换和捕获/回放操作会立即置位刷新标志；
- 静态边框和页面标题仍只在 `App_DrawStaticPage()` 中重画；
- 捕获页只清除图形框内部后重画曲线，其他页面不清除整块动态区域；
- 捕获波形由 `single_capture_replay` 按屏幕列抽点、限幅，再使用修复后的 `TFT_ST7789_DrawLine()` 连接相邻点，显示连续曲线。

## 2. 复制内容与自写内容

本次没有修改已有底层模块 `.c/.h`。新增正式组合模块 `single_capture_replay`，再把它的 `.c/.h` 从集成库复制到工程；屏幕、键盘和算法 API 仍来自工程 `modules` 中复制的正式模块。

新增或调整的均是 main 中的少量组合逻辑：环形键盘队列、SysTick 5 ms 调度、250 ms 屏幕刷新门控、底部状态栏绘制和字体枚举替换。

### 单次捕获异常修正

实测出现“波形不完整、尾部直线保留、斜线冲出框后卡死”。复核后确认不是 ST7789 字库问题，而是捕获窗口和显示边界同时缺少保护：旧窗口只有256点、预触发8点，门限在信号中后段时会截断；旧尾部判定接受单个毛刺；显示层没有对长度和端点做最终校验。

现已改为416点窗口、208点预触发；首尾活动必须连续3点，尾部必须留出8个安静点，否则本帧丢弃并继续等待。捕获槽位长度必须为2～416才允许绘图，X/Y端点均限制在图形框 `x=8..311、y=112..201` 内；回放长度超过256点时先线性重采样到DAC波表容量并调整更新率。这样半截波形不会被当成成功数据，异常坐标也不会触发底层驱动长时间绘制。

## 3. 验证结果

已使用 CCS 工程 Debug 配置重新编译链接，结果为：无编译错误、无链接错误、无警告；链接图显示 SRAM 使用约75.3%，剩余约2.7 KB。当前仅完成源码和链接验证，尚未连接开发板进行按键手感、屏幕观感和实际波形验证。
### 2026-08-19 捕获页卡死修正

调试器停在 `signal_tft_st7789.c` 的 `TFT_ST7789_DrawLine` 循环。最终确认根因是 Bresenham 实现直接在两个条件中计算 `2*err`：第一个条件可能先修改 `err`，导致第二个条件使用了不同的误差值，某些斜率下坐标不能正确收敛。正确实现先执行 `e2 = 2 * err`，两个判断都使用同一个 `e2`。

ST7789 的 `DrawLine()` 修复后，`single_capture_replay` 改回按列抽样、坐标限幅并使用 `DrawLine()` 连接相邻点。波形连续性比逐列短竖线更好，端点仍始终位于图框内。

### 2026-08-19 捕获链模块化

实板成功后的连续 ADC、COMP 通知、跨块触发搜索、416 点提取、首尾裁剪、三槽存储、自动坐标、安全绘图和 DAC 周期回放已整体整理到集成库 `02_acquisition/single_capture_replay`。`example04/main.c` 删除重复状态和绘图函数，只保留模块初始化缓冲区、COMP SysConfig 回调、GROUP1 中断通知、按键和页面文字。

工程模块目录新增 `signal_single_capture_replay.c/.h`。模块化版本使用 TI Arm Clang `-Wall -Werror` 完整编译、链接成功，生成 `Debug/signal_contest_template_final.out`。源码组织变化后仍需重新烧录做最后实板回归。
