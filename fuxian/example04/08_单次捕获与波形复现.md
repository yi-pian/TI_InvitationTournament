# 阶段八：单次捕获与波形复现

## 1. 模块选择与复制

本阶段直接选择集成库组合模块 `02_acquisition/single_capture_replay`，复制 `signal_single_capture_replay.c/.h`。同时复制 README 列出的依赖：双路同步 ADC、Trigger Capture、Arbitrary Wave、DAC DMA、ST7789 和 `signal_status.h`。所有文件均从集成库复制，工程内不修改模块 `.c/.h`。

组合模块内部完成：

```text
双 ADC 连续多块 DMA -> COMP 边沿通知 -> 相邻 DMA 块拼接
-> Trigger Find/Extract -> 首尾基线裁剪和完整性判断
-> S1/S2/S3 三槽存储 -> ST7789 自动 X/Y 安全绘图
-> Arbitrary Wave 重采样 -> DAC DMA 周期复现
```

## 2. SysConfig 配置

组合模块不新增硬件资源，完全复用各依赖模块 README：

1. ADC0/PA25 和 ADC1/PA17 使用同一 Timer Event，同步 DMA 采集。
2. COMP0 输入 PA27，内部 DAC 门限约 1.65 V，打开输出边沿中断。
3. MSPM0G3507 的 COMP0 CPU 中断函数必须为 `GROUP1_IRQHandler`。
4. DAC12 由 Timer Event 触发，DMA 重复输出波表。
5. ST7789 按屏幕 README 配置 SPI、CS、DC 和背光。

没有与 README 不同的 SysConfig 设置。`SIGNAL_COMP_INST` 和 IRQ 名称由工程生成，所以读取和清除 COMP 标志的小回调必须留在 `main.c`。

## 3. 从 README 复制到 main 的代码

初始化配置和 `Init/Arm/Service/SelectSlot/GetSelected/DrawSelectedST7789/ReplaySelected` 调用均来自组合模块 README 最小示例。当前参数为 1 MSPS、每块 416 点、三块连续 DMA、208 点预触发、三个槽位。

```c
g_module_status = SignalSingleCaptureReplay_Init(&g_single_capture,
    &capture_replay_config);

/* D 键 */
(void)SignalSingleCaptureReplay_Arm(&g_single_capture);

/* 主循环 */
if (SignalSingleCaptureReplay_Service(&g_single_capture) ==
        SIGNAL_RESULT_OK) {
    g_display_due = true;
}

/* 选择和回放 */
(void)SignalSingleCaptureReplay_SelectSlot(&g_single_capture, slot);
(void)SignalSingleCaptureReplay_ReplaySelected(&g_single_capture);
```

模块在触发点前后提取固定 416 点窗口，再按触发前基线、连续活动点和尾部安静点裁掉无效直线。任意波中间再次穿过门限不会被当作结束。

## 4. main 自写代码逐行解释

### COMP 回调

```c
static void App_ClearCaptureTrigger(void *context)
{
    (void)context;
    DL_COMP_clearInterruptStatus(SIGNAL_COMP_INST,
        DL_COMP_INTERRUPT_OUTPUT_EDGE | DL_COMP_INTERRUPT_OUTPUT_EDGE_INV);
    NVIC_ClearPendingIRQ(SIGNAL_COMP_INST_INT_IRQN);
}
```

1. `context` 是模块预留的上下文，本工程不用，所以显式忽略。
2. `DL_COMP_clearInterruptStatus` 清除上一次 COMP 边沿，防止武装后立刻误触发。
3. `NVIC_ClearPendingIRQ` 清除 CPU 中断控制器里的旧请求。

```c
static bool App_ConsumeCaptureTrigger(void *context)
{
    uint32_t edges;
    (void)context;
    edges = DL_COMP_getRawInterruptStatus(SIGNAL_COMP_INST,
        DL_COMP_INTERRUPT_OUTPUT_EDGE | DL_COMP_INTERRUPT_OUTPUT_EDGE_INV);
    if (edges == 0U) return false;
    DL_COMP_clearInterruptStatus(SIGNAL_COMP_INST, edges);
    return true;
}
```

1. `edges` 保存当前 COMP 原始边沿状态。
2. 没有边沿就返回 `false`，模块继续等待。
3. 有边沿时先清标志，再返回 `true` 告诉模块信号已经到来。

### 中断通知

```c
void GROUP1_IRQHandler(void)
{
    DL_COMP_IIDX index = DL_COMP_getPendingInterrupt(SIGNAL_COMP_INST);
    if ((index == DL_COMP_IIDX_OUTPUT_EDGE) ||
        (index == DL_COMP_IIDX_OUTPUT_EDGE_INV)) {
        SignalSingleCaptureReplay_NotifyTrigger(&g_single_capture);
        DL_COMP_clearInterruptStatus(SIGNAL_COMP_INST,
            DL_COMP_INTERRUPT_OUTPUT_EDGE | DL_COMP_INTERRUPT_OUTPUT_EDGE_INV);
    }
}
```

1. `index` 读取 GROUP1 中真正发生的 COMP 中断类型。
2. 只接受正向或反向输出边沿。
3. `NotifyTrigger` 只锁存标志，不在中断里处理 DMA 或 SPI。
4. 最后清除硬件标志，避免重复中断。

这是必须自写的硬件适配层，因为正式模块不能写死每个工程的 SysConfig 宏名。页面文字、按键到模块 API 的映射和 `g_display_due` 也是少量应用逻辑；跨块 DMA、搜索、裁剪、槽位、绘图和回放均不再由 main 编写。

## 5. 显示和复现

`DrawSelectedST7789()` 自动求当前槽位最小/最大值，使完整有效波形铺满 304x90 区域。它按屏幕列抽点，每个坐标限制在图框内，再调用修复后的 `TFT_ST7789_DrawLine()` 连接相邻列，显示连续曲线。修复后的 Bresenham 代码先保存一次 `e2 = 2 * err`，再用同一个 `e2`决定 X/Y 是否步进，避免第一次修改 `err` 后影响第二次判断。

`ReplaySelected()` 将槽位线性重采样到最多 256 点，并同比调整 DAC 更新率，使回放周期尽量保持不变。DAC DMA 使用 `repeat=true`，OUT 会持续输出周期波形。

## 6. 比赛操作和验证

1. 同一模拟信号接 PA25 和 PA27，并确保跨过约 1.65 V。
2. CAPTURE 页按 `D`，显示 `WAIT SIGNAL`。
3. 输入 50～200 us 单次任意波，成功后显示槽位、完整波形和 `DUR`。
4. 再按 `D` 依次保存到下一个槽位；三次后循环覆盖。
5. 按 `1/2/3` 选择并回放，按 `#` 重放当前槽位。

模块化工程已通过 TI Arm Clang `-Wall -Werror` 编译和链接。模块算法来自此前实板成功的版本；替换后的固件仍需重新烧录确认。
