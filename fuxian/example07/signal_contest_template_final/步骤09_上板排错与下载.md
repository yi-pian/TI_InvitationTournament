# 步骤09：上板排错与下载

## 1. `ADC ERROR` 的来源判断

当前 example07 的 `main.c` 没有 `ADC ERROR` 字符串。该字符串只存在于 `example05/signal_contest_template_final/main.c`，因此屏幕显示它时，优先判断为 CCS 下载了 example05 的旧 `.out`，而不是 example07 的双 ADC 测量代码主动显示了错误。

## 2. 本题的按键检测

已复制 `22_X` 的检测节奏：SysTick 每 1 ms 进入，静态计数达到 5 ms 后调用 `SignalMatrixKeypad4x4_ReadNewSymbol`，返回值保存到 `g_keypad_status`。模块完成行列扫描、3 次消抖与鬼键过滤。由于本题按键会启动扫频和 Lock-In，ISR 只投递字符，主循环执行耗时任务。

`A/D` 是循环翻页：A=上一页，D=下一页；首页按 A 也会切到谐波页，能够直接观察到按键有效。`1/2/3` 分别运行扫频、1 kHz 补偿和 1/2/3 次谐波补偿。

## 3. CCS 正确下载顺序

1. 在 CCS Project Explorer 选中 `example07/signal_contest_template_final`，不要选 example05。
2. 右键工程，执行 `Clean Project`，再执行 `Build Project`。
3. 在 Debug 配置中确认待下载文件是本工程的 `Debug/signal_contest_template_final.out`。
4. 下载并复位后，首页标题应为 `UNKNOWN CHANNEL COMP`；若仍出现 `ADC ERROR`，说明板内仍不是本工程的固件。

## 4. 已完成的离线验证

当前工程的 `main.c` 已用 TI Arm Clang 编译通过，且已重新链接生成 example07 的 Debug `.out`。这只证明工程构建正确；ADC 输入接线、未知网络连接和按键排线仍需上板验证。
