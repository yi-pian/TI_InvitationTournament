# 24_A/C_rebuild、22_X 与 example01–08 工程功能与模块详解

## 1. 范围与结论

本说明分析以下 11 个实际 CCS 工程：

- `24_A_rebuild/signal_contest_template_final`
- `24_C_rebuild/signal_contest_template_final`
- `22_X/signal_contest_template_final`
- `example01`～`example08` 各自的 `signal_contest_template_final`

这里把题目中的“`24_A\C_rebuild`”按现有目录解释为 `24_A_rebuild` 和 `24_C_rebuild`。没有把旧目录 `24_A`、`24_C`、`tmp/` 中的临时生成文件纳入统计。

这些工程的共同平台为 MSPM0G3507、CCS/CCS Theia、TI ARM Clang、MSPM0 SDK 2.11.0.07、SysConfig 1.28.0。程序均为裸机主循环，不使用 RTOS；硬件初始化统一从 `SYSCFG_DL_init()` 进入，外设访问以 TI DriverLib、Timer/Event、DMA 和中断为主。需要 FFT/均值/偏移等运算的工程复用 SDK 自带 CMSIS-DSP 1.16.2。

本次只做了源码与 SysConfig 静态审计，没有重新烧录或实板测量。11 个工程目录中都有现成 Debug 构建产物，但这只能作为历史编译证据，不能等同于“当前源码已经重新构建”或“硬件已经验证”。

## 3. 公共工程结构与复用边界

每个工程的核心文件用途基本一致：

| 文件/目录 | 作用 | 复用注意 |
|---|---|---|
| `main.c` | 赛题组合逻辑、状态机、页面和按键语义 | 最能体现题目流程；复制后要重新核对全局缓冲区大小和主循环时序 |
| `signal_config.h` | Fs、N、VREF、频段、DAC/DDS 参数 | 赛场改题优先改这里；部分 `main.c` 还有题目专用宏，也要一起检查 |
| `signal_contest_template.syscfg` | 芯片、时钟、ADC/DAC、Timer/Event、DMA、SPI/GPIO、IRQ 的配置源 | 必须用 SysConfig GUI/CLI 生成；不能直接照抄 `Debug/ti_msp_dl_config.*` |
| `modules/*.c/.h/.inc` | 冻结的采集、测量、DSP、显示、键盘和模拟前端模块 | 纯算法通常可整体复制；硬件模块必须连同 SysConfig 实例名一起迁移 |
| `COPIED_MODULES.md` | 模块来源和工程差异 | 可用来判断哪些模块是正式选择，哪些只是母版遗留 |
| `Debug/` | 自动生成文件、对象、map 和 out | 只读；行号索引也不指向这里 |

典型数据链为：

```text
SysConfig 初始化
  -> Timer 周期事件
  -> ADC/DAC 与 DMA 搬运
  -> DMA/外设 ISR 只更新完成标志或序号
  -> main 在帧边界执行算法
  -> TFT 局部/整页刷新
  -> SysTick 每 1 ms 提供键盘扫描和页面节拍
```

硬件模块最容易踩的坑是“只复制 `.c/.h`，没有复制实例名约定”。例如 `SignalDualADC_*`、`SignalADC_*`、`SignalDACDMA_MSPM0_*`、TFT、Capture 和比较器平台层都会引用 `ti_msp_dl_config.h` 中的实例宏；目标工程中的 ADC、Timer、Event、DMA 通道、IRQ 和 GPIO 名字必须匹配。

## 4. `24_A_rebuild`：放大器四问一体化测试

### 4.1 详细功能

该工程把 24_A 的四个问题做成 A/B/C/D 四种模式：

1. Q1 信号源与幅度控制：AD9850 产生可调频率，DAC 控制 VCA820，键盘输入频率或目标 Vpp；屏幕显示目标值、实际 DAC 码和状态。
2. Q2 扫频带宽：从 10 kHz 扫到 2 MHz，每点等待稳定并采集多帧 AC RMS；以低频参考增益的 0.707 倍寻找 -3 dB 截止点，显示峰值增益、截止频率和带宽。
3. Q3 压摆率：5 kHz 激励下以 2 MSPS 采集波形，先用 5%/95% 分位数求稳健 Vpp，再按 20%–80% 边沿计算上升/下降压摆率。
4. Q4 静态功耗：先让 AD9850 掉电，再轮询 `POWER_ADC` 采样电源测量通道，根据 24 V 电源、750 Ω 采样电阻和轨数系数换算静态电流/功耗。

当前应用层的大帧参数是 3.555556 MSPS、3072 点；功耗块为 256 点。`signal_config.h` 仍保留通用模板的 100 kSPS/1024 点参数，真正 Q2/Q3 的工作采样率以 `main.c` 的 `APP_*`/`MODE*_*` 宏和运行时 `SignalADC_SetSampleRate()` 为准。

### 4.2 模块与外设

| 功能组 | 模块文件 | 在本工程中的作用 |
|---|---|---|
| 外部 DDS | `ad9850.c/.h`、`ad9850_mspm0_platform.c/.h` | 125 MHz 参考时钟调谐字、GPIO 串行位流、复位、频率、相位和掉电控制 |
| 采集 | `signal_adc_dma.c/.h` | `SIGNAL_ADC` 的定时器触发单 ADC DMA；运行时切换采样率 |
| 幅值控制 | `signal_vca820_gain_control.c/.h` + `main.c` DAC 写码 | 将目标增益/Vpp 换算为 VCA820 控制电压和 12 位 DAC 码 |
| 精密测量 | `signal_robust_peak_to_peak`、`signal_slew_rate`、`signal_static_power` | Q3 稳健幅度/压摆率和 Q4 功耗计算 |
| 人机界面 | `signal_matrix_keypad_4x4`、`signal_tft_st7789*` | A–D 选题、数字输入、确认/清除、分题页面和局部刷新 |
| 公共依赖 | `signal_status.h`、`signal_types.h`、`signal_algorithm_status.h` | 统一状态码与测量类型 |

SysConfig 中的关键实例为 `SIGNAL_ADC`、`POWER_ADC`、`SIGNAL_SAMPLE_TIMER`、`DDS_GPIO`、`SPI_TFT`、`GPIO_TFT_CTRL`、`GPIO_KEYPAD`、`SIGNAL_UART`，并启用了片内 DAC12。功耗 ADC 是独立轮询链，波形 ADC 是 Timer/Event/DMA 链，两者不要混用。

### 4.3 主流程与复用建议

入口在 [`main.c:960`](24_A_rebuild/signal_contest_template_final/main.c#L960)。初始化顺序是 SysConfig → 单 ADC DMA → AD9850 → ST7789；主循环持续读键盘，Q1 立即应用参数，Q2–Q4 在模式切换后各执行一次完整测量并刷新页面。

复用时建议：信号源题复制 AD9850 平台层和 Q1；放大器带宽题复制 `App_RunQuestion2()` 与 `App_MeasureACRMS()`；压摆率题复制 Q3 及两个精密模块；功耗题复制 Q4，但必须按实际采样电阻、分压和双电源轨数量修改宏。

工程入口：[README](24_A_rebuild/signal_contest_template_final/README.md)、[SysConfig](24_A_rebuild/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](24_A_rebuild/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 114。

## 5. `24_C_rebuild`：动态双 ADC 波形识别与突发分析

### 5.1 详细功能

该工程同时覆盖周期信号和突发信号：

- 双 ADC A/B 由同一 Timer 事件同步触发。A 是经模拟调理后的信号通道，B 可作为门控/标记通道。
- 周期模式先把 12 位码按 3.3 V 和固定模拟增益 0.6 还原到输入电压，再去直流，计算均值、RMS、Vpp、偏度/峰度等时域统计量。
- CMSIS RFFT 配合 Hann 窗得到单边频谱；三点峰值与 Hann/Dirichlet 响应修正提高非整周期频率和幅值精度；`signal_harmonic`、`signal_multi_bin_energy` 聚合基波/谐波邻域。
- `ClassifyWaveform()` 综合频谱谐波比例、峰值因子、占空/时域特征，输出波形类型。
- 运行时根据实测频率选择下一帧采样率；切换采样率前停止 DMA，在帧边界重新配置 Timer，避免半帧混采样率。
- 突发模式使用连续多块 DMA、前一块+当前块拼接、ADC B 门控边沿和模拟通道包络双重判断，给出起止、持续时间和波形；屏幕只显示选中的稳定周期窗或突发窗。
- Timer Capture 独立测频，用来与 FFT 结果交叉验证。

### 5.2 模块与外设

| 功能组 | 模块文件 | 作用 |
|---|---|---|
| 双路采集 | `signal_dual_adc_mspm0g3507` | 有限帧、连续块、块序号快照、运行时改 Fs |
| 硬件测频 | `signal_timer_capture`、`signal_timer_capture_mspm0g3507` | Capture ISR、周期/频率结果 |
| 频谱 | `signal_harmonic`、`signal_multi_bin_energy` + `main.c` CMSIS RFFT | 基波、谐波和邻 bin 能量 |
| 波形显示 | `signal_tft_st7789*`、`signal_tft_waveform_st7789` | 坐标网格、自动缩放、折线和状态字段 |
| 应用自写 | `main.c` 的统计、Hann 峰值修正、分类、突发拼接 | 本题核心组合算法 |

SysConfig 实例为 `SIGNAL_ADC_A`、`SIGNAL_ADC_B`、`SIGNAL_DUAL_ADC_TIMER`、`SIGNAL_CAPTURE`、`SPI_TFT` 和 `GPIO_TFT_CTRL`。当前通用初始 Fs/N 为 100 kSPS/1024 点，允许的动态上限为 200 kSPS；突发布防直接使用最大采样率。

入口在 [`main.c:1035`](24_C_rebuild/signal_contest_template_final/main.c#L1035)。复用周期识别时可删除连续突发分支；复用突发时必须保留连续 DMA 块序号判定和相邻块拼接，不能只复制 `DetectBurstFromAnalog()`。

工程入口：[README](24_C_rebuild/signal_contest_template_final/README.md)、[SysConfig](24_C_rebuild/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](24_C_rebuild/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 108。

## 6. `22_X`：PLL 倍频控制与李萨如相位显示

### 6.1 详细功能

该工程把数字控制、双通道同步采样和相位显示组合在一起：

- 4×4 键盘的数字键设置 1–9 倍 PLL；应用层把倍频数写到 `GPIO_PLL_CTRL` 的四位控制线上。
- 独立按键设置 Y 通道量程/倍数和波形模式，对应 `GPIO_YV_CTRL`、`GPIO_WAVE_CTRL`。
- ADC0.2/PA25 与 ADC1.2/PA17 由同一 Timer/Event 同步采样，DMA 完成后用 `SignalDualADCPhase_Process()` 求 Y 相对 X 的相位；算法的频率比 `fY/fX` 使用当前 PLL 倍数。
- ILI9341 横屏绘制李萨如图，同时局部更新 PLL 倍数、Y 倍数、波形模式和相位。
- 1 ms SysTick 每 5 ms 扫描键盘；ISR 只处理键盘状态，不在 ISR 中刷新 TFT 或做 ADC 算法。

### 6.2 模块与外设

| 模块 | 作用 |
|---|---|
| `signal_dual_adc_mspm0g3507` | 双 ADC 同步 DMA |
| `signal_dual_adc_phase` | 双路动态中点、滞回、多过零平均相位 |
| `signal_matrix_keypad_4x4` | 扫描、消抖、鬼键过滤 |
| `signal_tft_ili9341`、平台适配层 | ILI9341 SPI 图元、文字、李萨如轨迹 |

SysConfig 还配置了 `GPIO_PLL_CTRL`、`GPIO_YV_CTRL`、`GPIO_WAVE_CTRL`。TFT 使用 SPI1，控制脚为 PB15/PB12；键盘使用 PB16/PB0/PB7/PB17 行和 PB18/PB13/PB20/PB4 列。

入口在 [`main.c:336`](22_X/signal_contest_template_final/main.c#L336)。当前 `signal_config.h` 的实际初始值是 100 kSPS/1024 点；`COPIED_MODULES.md` 中仍写有 500 kSPS，这是历史复制记录与当前源码的差异，复用时应以 `signal_config.h` 和运行时 `SignalDualADC_GetConfiguredRate()` 为准。

此外 Debug 目录存在多个 `.out`，自动烧录前必须明确选择目标文件。工程入口：[README](22_X/signal_contest_template_final/README.md)、[SysConfig](22_X/signal_contest_template_final/signal_contest_template.syscfg)、[实施文档目录](22_X)。函数定义总数 91。

## 7. `example01`：双通道可调信号分析仪

### 7.1 详细功能

这是 `22_X` 的 ST7789 通用化版本，重点是“采集参数可调、时域波形清晰、相位独立于显示阈值”：

- 每帧同步采集 X/Y 两路 1024 点，默认 100 kSPS。
- 波形区把一帧降采样为约 220 个横坐标点，绘制双通道时域轨迹；状态区采用局部清屏，减少闪烁。
- 相位模块自行从每路 min/max 得到动态中点并设置滞回，不依赖界面上的固定 `TH` 值。
- 键盘在 SysTick 中扫描后只把符号放入 8 项队列；主循环在 ADC 帧边界处理采样率、阈值和页面，避免改 Timer 时 DMA 正在工作。
- 用户已有记录显示 TFT 波形和键盘响应得到部分实机确认，但其他算法/全量程不能据此视为完整上板验证。

模块包括双 ADC、双 ADC 相位、通用相位辅助、4×4 键盘、ST7789 核心/平台/多尺寸字库和公共数学头。SysConfig 实例为 `SIGNAL_ADC_A/B`、`SIGNAL_DUAL_ADC_TIMER`、`SPI_TFT`、`GPIO_TFT_CTRL`、`GPIO_KEYPAD`。

入口在 [`main.c:286`](example01/signal_contest_template_final/main.c#L286)。若只需要相位测量，可复用 `SignalDualADCPhase_Process()` 及动态配置结构；若需要交互式分析仪，应连同按键队列和帧边界改采样率逻辑一起复制。

工程入口：[README](example01/signal_contest_template_final/README.md)、[SysConfig](example01/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](example01/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 97。

## 8. `example02`：DAC/DDS 扫频幅相测试

### 8.1 详细功能

该工程是一个片内激励的简易扫频仪：

1. `SignalFrequencySweep_Generate()` 预生成 500 Hz～8 kHz、16 点扫频表。
2. `SignalWaveOutput_SineWithOffset()` 通过软件 DDS/波表，把指定频率、Vpp、偏置换成 DAC 数据；DAC12 由独立 Timer 事件和 DMA_CH2 循环输出。
3. 双 ADC 同步采集输入和输出；ADC DMA 占用另外两个通道。
4. 应用层以 raw code 的 max-min 求两路 Vpp，并取比值得到增益；`SignalDualADCPhase_Process()` 求相位。
5. ST7789 逐点画幅频或相频曲线。A/B 切换曲线，C 清屏重扫，D 改采样率。

### 8.2 模块

| 功能 | 模块 |
|---|---|
| 波形输出 | `signal_dac_dma_mspm0g3507`、`signal_dac_wave_table`、`signal_dds`、`signal_wave_output_mspm0g3507` |
| 波形形状 | `signal_sine`、`signal_square`、`signal_triangle`、`signal_sawtooth` |
| 扫频 | `signal_frequency_sweep` |
| 采集/相位 | `signal_dual_adc_mspm0g3507`、`signal_dual_adc_phase`、`signal_phase` |
| UI | `signal_matrix_keypad_4x4`、`signal_tft_st7789*` |

SysConfig 包含 ADC A/B、双 ADC Timer、DAC12、DAC Timer、SPI TFT 和键盘 GPIO；资源差异是 DAC DMA 使用 DMA_CH2，迁移时必须重新检查双 ADC 的 DMA 通道，避免冲突。

入口在 [`main.c:231`](example02/signal_contest_template_final/main.c#L231)。当前 Vpp 是原始码峰峰值，未做模拟前端增益/偏置校准；对精密幅频题应先转电压并做通道增益/延迟校准。工程现有的主要 `.out` 名为 `wave_output_validation.out`，烧录前应确认这是期望产物。

工程入口：[README](example02/signal_contest_template_final/README.md)、[SysConfig](example02/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](example02/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 136。

## 9. `example03`：双通道数字示波与 XY 显示

### 9.1 详细功能

该工程以 256 点短帧和 220 点显示轨迹实现轻量双通道示波器：

- 双 ADC 同步 DMA 采集 A/B；默认 100 kSPS，频段目标 1–10 kHz。
- 每帧先把 raw code 转为 0–3.3 V，再用 CMSIS `arm_mean_f32()` 和 `arm_offset_f32()` 原地去直流。
- 页面可显示 CH1、CH2、双通道时域或 XY/李萨如；横向有 4 档，纵向有 7 档。
- 局部擦线不是简单整块清黑：`App_BackgroundColor()`、`App_RestoreLine()` 会恢复网格颜色，再绘制新轨迹，减少闪烁。
- 键盘事件先入队，再在主循环帧边界改变页面和档位。

目录同时带有 `signal_adc_pingpong_dma` 和 `signal_adc_ring_buffer`，适合继续扩展真正的连续流、触发前历史或事件 FIFO；当前 `main.c` 主路径实际调用的是 `SignalDualADC_Start()` 有限帧接口，这两个模块不是当前主循环的数据源。

## 10. `example04`：综合信号分析、发生、捕获与回放母版

### 10.1 详细功能

这是 11 个工程中功能最全、也最适合做比赛母版的工程。主程序有多页工作模式：

- 可编程发生：正弦/方波/三角/锯齿波，统一使用频率、Vpp、偏置三参数，经波表和 DAC DMA 连续输出。
- 基本测量：按 `00_docs/recipes` 直接完成 ADC code 转电压、均值、min/max、Vpp、RMS、AC RMS 和削顶检测，再应用既有增益/偏移校准与总体标准差计算。
- 多种测频：ADC 过零、线性过零插值、CMSIS FFT 插值和比较器+Timer Capture 硬件测频。
- 频谱：按 Recipe 去直流、窗函数、CMSIS Q15 FFT/幅值、主峰插值、谐波、THD、SNR、SFDR、多 bin 能量。
- 抗毛刺：MAD、中值、Hampel、稳健 Vpp、稳健 RMS。
- 精密正弦：三参数/四参数正弦拟合与 Lock-In。
- 校准：ADC 两点增益/偏移和双通道固定延迟。
- 单次捕获回放：ADC0 连续 DMA，COMP0/PA27 只标记门限边沿；三块 DMA 拼接后保留触发前后数据，裁掉首尾基线，存入 S1/S2/S3；可选择槽位并通过 DAC DMA 周期回放。
- ST7789 多页显示和 4×4 键盘参数编辑。

默认分析帧为 100 kSPS/512 点。单次捕获页单独使用 1 MSPS、每块 416 点、3 DMA 块、208 点预触发、3 个槽位。缓冲区很多，移植时必须同时核对 RAM 和栈；当前大数组均为静态存储，不能随意改成局部数组。

## 11. `example05`：AD9833 阻抗分析与 RLC 识别

### 11.1 详细功能

该工程使用外部 AD9833，而不是片内 DAC：

1. 独立 `SPI_AD9833` 和 FSYNC GPIO 初始化 25 MHz MCLK 的 AD9833。
2. 生成 1 kHz～100 kHz、32 点对数扫频表；每次设置一个正弦频点并等待稳定。
3. 同步 ADC A/B 分别解释为电流通道和 DUT 电压通道，500 kSPS、2048 点。
4. 两路分别去均值并求 RMS；用 `|Z|=Vrms/Irms`，用正交投影求电压相位减电流相位。
5. 在全扫频数据上拟合串联 R/L/C，寻找谐振点和阈值交点，计算带宽与 Q，判断 R/L/C/串联谐振特征。
6. ST7789 显示每点实时值和最终 RLC、f0、BW、Q；保持 1.5 s 后自动重新扫频。

模块为 `ad9833`、`mspm0_blocking_bus`、双 ADC、扫频和 ST7789。`signal_phase`、`signal_dual_adc_phase`、键盘及片内 DAC/DDS 波形模块仍留在目录中，但当前主流程没有使用其中多数文件。

特别注意：`.cproject` 已把以下旧片内波形源从 Debug 构建排除：`signal_dac_dma_mspm0g3507.c`、`signal_dac_wave_table.c`、`signal_dds.c`、`signal_sine.c`、`signal_square.c`、`signal_triangle.c`、`signal_sawtooth.c`、`signal_wave_output_mspm0g3507.c`。函数索引仍收录这些目录内函数，并标注 `〔构建排除〕`，避免误认为它们是当前激励链。

SysConfig 包含双 ADC、共享 Timer、`SPI_TFT`、`SPI_AD9833`、`GPIO_AD9833` 和键盘 GPIO。模拟前端的 `SIGNAL_CURRENT_SCALE_A_PER_CODE` 当前只是占位式 3.3/4095，若电流通道使用跨阻放大器，必须改成包含跨阻增益、分压和偏置的真实 A/code 标定值，否则 R、L、C 都没有物理可信度。

入口在 [`main.c:460`](example05/signal_contest_template_final/main.c#L460)。工程入口：[README](example05/signal_contest_template_final/README.md)、[SysConfig](example05/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](example05/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 155（包含目录内构建排除源）。

## 12. `example06`：单 ADC 弱信号自动测量

### 12.1 详细功能

该工程针对 10–100 kHz、单通道输入：

- `SIGNAL_ADC` 以 500 kSPS、1024 点单帧 DMA 采集。
- 应用层先把 ADC 码转换为电压并去直流，做 1024 点 CMSIS fast RFFT；只在目标频段 bin 内找峰，利用邻点插值得到频率/幅值候选。
- 同时运行上升过零和过零插值；从多个过零周期中选择最接近 FFT 目标频率的周期，避免谐波或噪声导致错误周期。
- 计算峰峰值，并按主频相位把连续 1–5 个周期重采样到 312 像素宽度；纵轴按当前帧幅度自动量程。
- 数字键 1–5 选择屏幕显示周期数，键盘仍按 1 ms SysTick/5 ms 扫描。

模块为 `signal_adc_dma`、`signal_zero_cross`、`signal_zero_cross_interpolation`、4×4 键盘和 ST7789/字库。SysConfig 只需要单 ADC、采样 Timer、SPI TFT 和两个 GPIO 组，比双 ADC 工程资源更轻。

入口在 [`main.c:390`](example06/signal_contest_template_final/main.c#L390)。该工程同时在根目录保留了 SysConfig 生成的 `ti_msp_dl_config.c/.h`，它们属于生成文件，不应手改。静态审计发现本工程 `.syscfg` 缺少其他工程都有的 `@versions` 元数据；现有文件仍可被识别，但换 CCS/SysConfig 版本时应先在 GUI 中确认工具版本再 Generate。

工程入口：[README](example06/signal_contest_template_final/README.md)、[SysConfig](example06/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](example06/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 73。

## 13. `example07`：未知通道频响与自动补偿

### 13.1 详细功能

该工程以“测量未知通道 → 建表 → 反向补偿”为主线：

- DAC12+DMA 以 DDS 波表产生 500 Hz～10 kHz 激励；双 ADC 同步采集输入和通道输出。
- 对两路分别做 Lock-In，得到目标频率的幅值与相位；输出/输入比形成增益和相位响应。
- `App_RunSweep()` 建立 16 点频响表。
- `SignalFrequencyResponseCorrection_Process()` 对表格做插值/校正；`App_Run1kCompensation()` 生成 1 kHz 预补偿并回测残余误差。
- `App_RunHarmonics()` 分别测量基波、二次、三次通过未知通道后的响应，再把反向幅相系数合成进 DAC 波表，形成预失真补偿。
- 键 1/2/3 运行扫频、1 kHz 补偿、谐波补偿；A/D 切页面。

模块为双 ADC、DAC DMA、波表、正弦、DDS、扫频、Lock-In、频响校正、键盘和 ST7789。默认采集 500 kSPS/1024 点，DAC 更新率 500 kHz；`main.c` 的实际扫频是 500 Hz～10 kHz，目标 1 kHz，而 `signal_config.h` 仍保留若干 10 kHz 通用宏。复用时应以具体调用传入的宏为准，并清理重复参数，避免调错。

SysConfig 与 `example02` 类似：双 ADC Timer + 独立 DAC Timer，DAC12，SPI TFT 和键盘 GPIO。入口在 [`main.c:378`](example07/signal_contest_template_final/main.c#L378)。工程入口：[README](example07/signal_contest_template_final/README.md)、[SysConfig](example07/signal_contest_template_final/signal_contest_template.syscfg)、[模块记录](example07/signal_contest_template_final/COPIED_MODULES.md)。函数定义总数 108。

## 14. `example08`：片上 OPA/GPAMP/比较器模拟前端

### 14.1 详细功能与接线

这是专门演示 MSPM0G3507 片上模拟资源的工程，不是软件模拟运放：

- 外部带 1.65 V 偏置的正弦只接 PA26，并与板 GND 共地。LP-MSPM0G3507 的 J18 默认把 PA26 连到光敏电路，外部输入前必须拔掉 J18。
- PA26 同时以高阻方式进入 GPAMP 和 COMP0。GPAMP Buffer 输出由 ADC1 内部 CH14 采样；OPA0 单位增益 Buffer 输出由 ADC0 内部 CH13 采样。
- OPA1 缓冲 COMP.DAC8 基准，供诊断页观察。PA24 在当前版本不用，不能再与 PA26 短接。
- 双 ADC 同步采集 500 kSPS、512 点；主页面绘制两条内部模拟链的李萨如轨迹，并用双 ADC 相位算法验证两条同相缓冲路径应接近 0°。
- COMP0 有约 1.65 V 过零和约 2.0 V 固定门限两种模式。硬件 IRQ 统计上升/下降边沿；应用层也按同一门限对 ADC 帧做软件计数，便于对照。
- 诊断页显示 GPAMP/OPA 增益预算、ADC 内部通道和 COMP DAC 码。

## 16. 已发现的复用风险

1. 多数 README 前半仍保留“空母版、不预装模块”的通用文字，但实际目录已经包含并调用了模块；判断功能应以 `main.c`、`COPIED_MODULES.md` 和 `.syscfg` 为准。
2. `22_X` 的模块记录写 500 kSPS，当前 `signal_config.h` 写 100 kSPS。比赛前应统一文档、Timer 实际频率和相位算法频率比。
3. `example05` 的片内 DAC/DDS 文件只是母版遗留并被 Debug 构建排除；当前激励源是 AD9833。
4. `example06` 的 `.syscfg` 缺少 `@versions` 元数据，且根目录有生成文件；换工具版本时先用 SysConfig 重新生成，不要手改生成代码。
5. `22_X`、`example04` 等 Debug 目录存在多个 `.out`；烧录脚本无法安全自动选择，必须人工确认。
6. 任何 `Build 成功` 都不代表接线、输入范围、参考地、模拟偏置、屏幕型号和板上跳线正确。尤其 `example08` 的 PA26/J18、`example05` 的跨阻标定和 AD9833 MCLK 必须实测确认。
7. 函数行号会随源码修改变化；运行 `python tools/generate_function_index.py` 可刷新配套的函数索引。

配套文档：[工程函数分类复用索引](工程函数分类复用索引.md)。
